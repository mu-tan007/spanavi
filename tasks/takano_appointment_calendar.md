# 高野さんの当社登録アポを架電カレンダーに表示（2026-09-06）

## 目的
フラーレンの高野さんについて、架電の一画面集中ページのカレンダータブで、当社が登録した面談日時・訪問先エリアを確認できるようにする。アポ取得報告の保存・日時変更を反映する。

## 実装方針
- 既存の担当者・クライアント・アポの関連付けと保存経路を確認する。
- 当社登録の面談予定を担当者単位で表示する。外部カレンダーがない担当者にも表示する。
- 面談日、時刻、会社名、訪問先の都道府県（あれば住所・面談方法）を表示する。
- 当社登録分だけであり、空欄は本人の空き時間を保証しない旨を明記する。
- アポ保存成功後、日時変更・削除後の表示を再取得する。取得失敗を予定なしと扱わない。
- 他担当者のSpirリンク・既存Googleカレンダーを維持する。

## 検証結果
- 本番の読み取り照合: 高野さんの担当リスト18件。2026年9月のアポ11件からキャンセル・日時未確定リスケを除外し、表示対象8件。本人とクライアント共通の外部カレンダー設定が空であることも確認。
- 既存のアポ取得報告はDBに時刻・訪問先を保存していたが、親へ返す値に時刻がなく、一般架電者にはsetAppoDataも渡されていなかった。共通保存成功イベントと独立した読み取りで両方を解消。
- 全案件の担当IDを優先して分類。IDのない旧リストは同一クライアント内で一意に一致する担当名だけ解決する。複数担当の案件は注記する。
- 表示中は60秒ごと・フォーカス復帰・更新ボタンで再取得。失敗はエラー表示し、古い応答が別担当者の画面へ入らないようにする。
- 日付のみのUTC午前0時を09:00と誤認しない。リスケ日時は事前確認画面の既存の文字列時刻契約に合わせる（rescheduled_atの月境界はUTC、meeting_dateはJST）。
- Vitest 131件成功。Reactで実コンポーネントをマウントし、保存通知、日付選択、月移動、エラー復旧、担当切替競合、Spirリンク維持を確認。
- npm run build 成功。既存の大きなチャンク／動的・静的import混在の警告あり。
- npm run check:functions はローカルの管理トークン未設定によりスキップ。今回Edge Function/DBスキーマ変更なし。
- 接続可能なブラウザがなく、ブラウザでの目視は未実施。Reactレンダー検証と本番データの読み取り照合で確認した。
- 本番DBへのテスト書き込み、通知送信、既存データの変更は行っていない。

## 仕様上の範囲
- 外部連携のない担当者のカレンダータブに当社登録アポを表示する。Spir/Google連携済み担当者は既存表示を維持。
- 担当する全リストのアポを現在の担当設定で分類する。担当変更前の担当者を固定する履歴スナップショットは今回追加しない。
- 本人の全予定・終了時刻・移動時間を示すものではなく、訪問先都道府県が住所にない場合は「都道府県未登録」と明示する。
